# Role-Specific Interview Versions for 5 to 7 Years Experience

This file tailors the same project background and experience into different interview narratives depending on the role. Use the section that best matches the job you are applying for.

## 1. Python Backend Engineer

### How to introduce yourself
I am a software engineer with around 5 to 7 years of experience working on backend and platform-oriented systems, with strong exposure to Python, API-related flows, debugging, production issue handling, and migration work. In my recent work, I have handled bug fixing, feature changes, RCA-based fixes, and production-safe improvements across networking, certificate handling, internal tooling, and service behavior.

### What to emphasize
- Python development and debugging
- Backend logic and service behavior
- API consistency and request/response handling
- Root-cause analysis and production issue resolution
- Writing safe fixes without breaking existing behavior
- Migration and compatibility work such as Python 3 related updates

### Best project examples to use
- Python 3 migration related work where behavior compatibility mattered
- REST API fixes or consistency improvements
- Internal DLP policy translation or data-handling flows
- Bug fixes where investigation, validation, and safe deployment mattered

### How to describe your strengths for this role
My strength as a Python backend engineer is that I do not just implement logic, I also think about correctness, maintainability, failure cases, and how the code behaves in production. I am comfortable debugging existing systems, improving reliability, and making targeted backend fixes with clear RCA.

### Example interview answer for why you fit this role
This role matches my experience well because I have worked extensively on backend-oriented engineering problems, including debugging production issues, improving service behavior, handling migrations, and making safe logic changes in existing systems. I am especially comfortable in roles where Python, APIs, reliability, and practical problem solving are important.

### STAR examples that fit best
- Challenging bug
- Migration work
- Backend/API issue
- Performance issue
- Ownership example

## 2. Platform or Sustaining Engineer

### How to introduce yourself
I am a software engineer with around 5 to 7 years of experience in sustaining, platform, and production-focused engineering work. A large part of my work has involved understanding complex existing systems, investigating defects across module boundaries, fixing stability issues safely, and supporting long-lived enterprise codebases.

### What to emphasize
- Sustaining engineering mindset
- Working in mature and complex codebases
- RCA-driven debugging
- Production-safe fixes and backport-friendly changes
- Platform behavior, OS interaction, and system-level understanding
- Cross-module issue ownership

### Best project examples to use
- Route reconciliation and PF_ROUTE related debugging
- SNMP monitoring and platform component issues
- Certificate and FIPS mode issues
- Migration work that required compatibility preservation
- Stability-focused bug fixes in sensitive areas

### How to describe your strengths for this role
My strength in platform or sustaining roles is that I can work effectively in complex existing systems where the problem is not obvious. I am comfortable reading unfamiliar code, tracing real failure paths, narrowing the root cause, and delivering low-risk fixes that fit production constraints.

### Example interview answer for why you fit this role
I fit this role because much of my experience has been in sustaining-type engineering work where the key requirement is not only writing new code, but understanding system behavior, fixing issues under constraints, and making changes that are safe for long-running enterprise products.

### STAR examples that fit best
- Challenging bug
- Production issue
- Ownership example
- Security fix
- Conflict with team when deciding fix scope

- Log-based and behavior-based debugging

- Production issue investigations with environment-specific behavior

This role fits me because I have strong hands-on experience with production-style debugging, RCA, validation, and issue ownership. I am comfortable working on problems where the first symptom is misleading and where reliability matters more than quick but risky code changes.

### STAR examples that fit best

- Ownership example

I fit a senior software engineer role because my work has gone beyond isolated coding tasks. I have handled ambiguous production problems, driven fixes across modules, balanced short-term delivery with long-term maintainability, and taken ownership from investigation through final validation.

## 5. How to Adapt the Same Experience by Role

### If the same project is asked in different interviews
- For Python backend engineer: focus on Python logic, APIs, data flow, reliability, and maintainable fixes.
- For platform or sustaining engineer: focus on system behavior, RCA, OS interaction, stability, and safe change scope.
- For production support engineer: focus on triage, debugging, logs, minimal-risk fixes, and incident resolution.
- For senior software engineer: focus on ownership, decision making, tradeoffs, coordination, and long-term maintainability.

## 7. Final Guidance

- Do not change your core experience; change the emphasis.
- Choose examples based on what the role values most.
- Keep your introduction aligned with the job description.
