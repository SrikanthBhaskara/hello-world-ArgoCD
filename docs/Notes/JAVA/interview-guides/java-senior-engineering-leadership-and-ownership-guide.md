# Java Senior Engineering Leadership and Ownership Guide

## Purpose

This file helps 5 to 7 year engineers prepare for senior-level behavioral and engineering leadership questions.

Use it for:
- ownership questions
- code review and mentoring discussions
- design disagreement questions
- senior engineer vs senior developer expectation gap

## What Changes at 5 to 7 Years

You are no longer judged only on the code you write.

Interviewers also expect:
- influence on code written by others
- stronger design judgment
- better decision-making under ambiguity
- mentoring and enablement
- operational ownership
- communication with peers and stakeholders

## Senior Engineer vs Strong Developer

A strong developer can implement difficult work well.

A strong senior engineer should also:
- reduce risk for the team
- improve standards
- make others faster
- prevent repeated mistakes
- guide design decisions
- own outcomes, not only tasks

## Topics You Must Be Ready For

### Code Review
Explain how you review for:
- correctness
- readability
- maintainability
- failure handling
- performance risk
- security risk
- test coverage quality

### Mentoring
Examples can include:
- onboarding help
- architecture explanation
- debugging support
- review feedback that improved another engineer's code
- standardization and documentation work

### Technical Disagreement
A senior answer should show:
- calm reasoning
- constraint-driven discussion
- willingness to align on facts
- respect for tradeoffs
- decision closure once the team aligns

### Ownership
Ownership means:
- noticing problems without waiting to be assigned
- following an issue through recovery and prevention
- improving weak spots in documentation, alerts, or delivery flow

## Questions You Should Be Ready For

- Tell me about a time you mentored someone.
- Tell me about a design disagreement and how you handled it.
- How do you review code written by other engineers?
- How do you decide when to push back on a requirement?
- How do you balance delivery speed and code quality?
- How do you handle a mistake in production?
- How do you improve engineering standards without authority over everyone?

## Good Senior Answer Shape

1. context
2. challenge or risk
3. what decision you made
4. tradeoff or reasoning
5. result
6. what improved afterward

## Strong Senior Examples to Prepare

### Code Review Example
Talk about a case where you caught:
- unsafe retry logic
- weak error handling
- broken transaction boundary
- concurrency issue
- maintainability problem hidden behind working code

### Mentoring Example
Talk about how you helped someone:
- understand a system faster
- debug a production issue
- improve code quality
- become more independent over time

### Design Disagreement Example
Talk about how you:
- reframed debate around constraints
- avoided opinion-only argument
- compared alternatives
- aligned the team on a practical path

### Ownership Example
Talk about how you:
- noticed a hidden risk
- fixed the immediate problem
- introduced a long-term improvement
- reduced future operational pain

## Strong Senior Phrases

- "I try to review for long-term operability, not only whether the code passes today."
- "Mentoring for me means making other engineers more effective, not only answering questions."
- "In disagreements, I try to anchor the conversation on constraints, failure modes, and measurable impact."
- "Ownership includes reducing recurrence, not only closing the immediate ticket."
- "A senior engineer should improve team outcomes even when the task is not directly assigned."

## Mistakes to Avoid

- describing mentoring only as helping once in chat
- talking only about your personal contribution with no team impact
- making disagreement stories sound ego-driven
- describing ownership as simply finishing assigned tasks
- giving generic statements with no concrete example

## Practice Prompts

1. Prepare one strong mentoring story.
2. Prepare one code-review catch that mattered.
3. Prepare one incident ownership story.
4. Prepare one disagreement story with balanced tradeoffs.
5. Prepare one example where you improved process or engineering standards.
